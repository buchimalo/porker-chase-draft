# ポカチェ ドラフト会議

ポーカーチェイス フレンドマッチのチーム分けをドラフト形式で行うための Web アプリ。
Firebase Realtime Database を使って、メインボードと各チームの指名シートがリアルタイムに同期します。

## 画面

| 画面 | ファイル | 用途 |
| --- | --- | --- |
| メインボード | `index.html` | 進行・抽選・管理（配信に映す画面） |
| 指名シート | `team-sheet.html?team=team1` | 各チームが選手を指名する画面 |
| 結果一覧 | `draft-results.html` | 全チームの指名結果 |

## URL パラメータ

| パラメータ | 効果 |
| --- | --- |
| `?team=team1` | 指名シートのチーム指定（省略時はチーム選択画面） |
| `?admin=1` | 管理モードを有効化。以後その端末では省略可（`?admin=0` で解除） |
| `?view=1` | 観戦モード。管理ボタンを隠す（視聴者に共有するURL向け） |
| `?obs=1` | 配信モード。背景透過・指名ボードのみ表示（OBS のブラウザソース用） |
| `?demo=1` | 練習モード。Firebase を使わず端末内だけで動作（本番データに影響しない） |

例:
- 進行役（自分）: `index.html?admin=1`（一度開けば以後は `index.html` だけでOK）
- 配信用オーバーレイ: `index.html?obs=1`
- 視聴者共有用: `draft-results.html?view=1`
- リハーサル: `index.html?demo=1` と `team-sheet.html?demo=1`（同じPCの別タブ同士は同期します）

## 主な機能

### 管理モード

管理系の操作（巡目の移動・設定・リセット・抽選・指名の取り消し）は **管理モードの端末でのみ表示**されます。
ボードのURLをそのまま視聴者や監督に共有しても、管理ボタンは出ません。

- 有効化: `index.html?admin=1` を一度開く（`localStorage` の `pcd.admin` に記録されます）
- 解除: `index.html?admin=0`
- `?view=1` `?obs=1` は常に管理モードOFF、`?demo=1`（練習モード）は常にON

> これは画面上の表示制御です。データベース自体の保護は Firebase のセキュリティルールで行ってください。

### メインボード
- **指名ボード** — チームごとのカード表示。チームカラー・指名順（スネーク：偶数巡は逆順）・進捗バー。
- **重複の自動検出** — 同じ選手が複数チームに指名されると自動でハイライトし、「抽選が必要です」と表示。
- **抽選（ポーカー勝負）** — 重複した選手ごとに、該当チームへ5枚ずつ配って1枚ずつめくり、役の強さで交渉権を決めます。
  4枚目でリード表示、最後の1枚で決着。当選チーム以外は自動的に「抽選負け」となり再指名待ちになります。
  逆転はおよそ35%の確率で発生します（`js/showdown.js` の `dramaChance` で調整）。

  > 勝者は先に完全ランダム（各チーム 1/N）で決めたうえで、その勝者が勝つ配牌を探しています。
  > 演出のために勝敗を操作してはおらず、勝率は均等、画面に出る役と勝者も常に一致します。
- **ルーレット抽選** — 選手が足りないときの「枠」を作れます。ポーカー抽選とは別枠の演出です。
  1. 選手リスト編集の「🎰 ルーレット枠を追加」で `ルーレット①` `ルーレット②` … を選手リストに入れる
  2. 「ルーレット対象を編集」で、盤の出目になる選手（最大10名）を登録する
  3. 監督は候補選手リストから `ルーレット①` を普通に指名する（仮出しでのフェイントも可能）
  4. 進行役がボードの「ルーレットを回す」で盤を回し、止まった1名がその監督の指名として確定する

  **枠は番号順に1つずつしか使えません。** `ルーレット①` を消費するまで `ルーレット②` 以降は候補リストで選べず、
  「順番待ち」と表示されます。①が回されて当選者が決まると、次に②が選べるようになります。

  同じ枠を複数チームが指名した場合は**通常の重複と同じくポーカー抽選**になり、勝った1チームだけが回せます。
  一度使った枠と、既に確定した選手は盤・候補リストから自動で外れます。

  > 当選者を先に均等ランダムで決めてから、そこで止まるように盤を回しています。
  > 画面に出る出目と結果は常に一致します。

- **再指名不可チェック** — 過去の巡で確定済みの選手が再度指名されると「◯巡目で指名済み」と警告。

- **同じ巡での指名ロック** — 1つの巡は「全員が出す → 重複を抽選で決める → 負けた監督が出し直す」の繰り返しで進みます。
  この 1 回ぶんを**提出フェーズ**と呼びます。**前のフェーズで確定した選手は、後のフェーズでは指名できません。**

  - 最初の同時提出（フェーズ0）— 誰もロックされません。重複したらポーカー抽選です。
  - 抽選に負けた監督の再指名（フェーズ1）— 単独指名で確定した選手も、抽選に勝って獲得された選手も選べません。
  - **同じフェーズで再指名している監督同士は被せられます。** 敗者が2人いて同じ選手を出したら、もう一度ポーカー抽選です。

  > フェーズは指名データの `attempts`（抽選に負けた回数）で判定しています。
  > 進行役が指名を取り消した場合は、その巡が一度完了していれば確定済みをすべてロックします（`settings/allIn` に記録されます）。
- **伏せモード / 一斉公開** — 全チームが送信するまで指名を伏せ、任意のタイミングで一斉公開できます（既定はオフ）。
- **監督（チーム）の管理** — 管理パネルから監督の追加・改名・削除・並べ替え・**イメージカラーの設定**ができます。色は各行の色見本から選び、ボード・指名シート・結果一覧すべてに反映されます（未設定の監督は登録順のパレットで補います）。並び順がそのまま指名順（前節上位から）になり、偶数巡は自動で逆順に。各行の 🔗 で、その監督に渡す指名シートのURLをコピーできます。
- **管理パネル（⚙）** — 手動での抽選負け設定、指名の取り消し、総巡目数の変更、候補選手リストの編集、ドラフトのリセット。
- **キーボード操作** — `←` `→` で巡目を移動。

### 指名シート
- チーム選択（端末に記憶）、巡目の自動追従。
- **候補選手リストから選択** — 検索付き。登録選手は常に50音順で並びます。過去の巡で指名済みの選手はグレーアウト、他チームが指名中の選手は `⚔ チーム名` を表示。
  全チームが出し揃った後は、その巡で確定済みの選手もグレーアウトして選べなくなります。
- 送信前の確認モーダルに注意事項（再指名不可・重複による抽選）を表示。
- 抽選に負けると赤い「再指名してください」表示に切り替わります。

### 結果一覧
- カード表示 / 一覧表（巡目 × チームのマトリクス）を切替。
- 抽選の記録（対象選手・獲得チーム・抽選負けチーム）を表示。
- 印刷 / PDF 出力に対応。
- **テキストで保存** — カード表示と同じ「チーム別の指名一覧」を `.txt` でダウンロードできます
  （UTF-8 BOM + CRLF なので Windows のメモ帳でそのまま開けます）。
  ファイル名は `pokachi-draft-YYYYMMDD-HHMM.txt`。メインボードの「結果一覧」からも保存できます。

## データ構造（Realtime Database）

```
draft/
  currentRound: 1
  teams/
    team1/ { id, name, order, icon?, color? }   # order  = 指名順（1 始まり）
                                                # color  = 監督のイメージカラー（未設定なら既定パレット）
  nominations/
    round1/
      team1/ { playerName, teamName, timestamp, status, attempts? }
  settings/
    totalRounds: 6
    hidePicks: false
    revealed/ { round1: true }
    allIn/ { round1: true }        # 全チームが確定した巡（以後その巡はロック）
  players: "選手A\n選手B\n..."   # 候補選手リスト（1行1名）
  roulette: "助っ人A\n助っ人B\n..."   # ルーレット対象（最大10名）
                                  # 枠（ルーレット①…）は players 側に入れる
  rouletteLog/
    round1/
      team1/ { playerName, teamId, teamName, candidates, timestamp }
  lottery/
    round1/ { <選手キー>: { playerName, winnerTeamId, winnerTeamName, loserTeamNames, timestamp } }
```

`status` は `confirmed`（確定）または `lost_lottery`（抽選負け）。
ルーレット枠の指名は、回すまで `playerName` が `"ルーレット①"` のままです。
当選すると `playerName` が実際の選手名に変わり、`rouletteWon: true` と
`rouletteSlot: "ルーレット①"`（使用済みの枠）が入ります。
`attempts` には抽選に負けた過去の指名が入り、履歴に残ります。

既存データとの互換性を保つため、`settings` / `players` / `lottery` は存在しなくても既定値で動作します。

> 注意: `settings` `players` `lottery` は今回追加したパスです。Firebase のセキュリティルールで書き込みが
> 制限されている場合は、これらのパスへの書き込みを許可してください。

## ファイル構成

```
index.html            メインボード
team-sheet.html       指名シート
draft-results.html    結果一覧
css/style.css         全画面共通のスタイル（デザイントークンは先頭の :root にまとめてある）
js/core.js            Firebase 初期化・共通ロジック（重複検出、順序計算、練習モード等）
js/showdown.js        抽選のポーカー勝負（配牌・役判定・逆転制御）
js/roulette.js        ルーレット抽選の盤面と回転演出
js/main.js            メインボード
js/team-sheet.js      指名シート
js/draft-results.js   結果一覧
```
